The Predictive Opportunity Intelligence Dashboard is a full-stack React + Express application that ingests federal and alternative data signals (SAM.gov, openFDA, ClinicalTrials.gov, USASpending.gov, arXiv, SEC EDGAR, USPTO) and synthesizes them into predictive intelligence using Google Gemini.

This guide walks you through cloning the app, configuring credentials, running the dev server, producing a production build, and deploying to Google Cloud Run with GCP Secret Manager.

## Prerequisites

- **Node.js 18+** or **Bun**
- A **Google Gemini API key** (`GEMINI_API_KEY`) — obtain one from [Google AI Studio](https://aistudio.google.com/)
- A [Firebase](https://console.firebase.google.com/) project (for Firestore persistence used by the entity knowledge graph and extraction studios)
- *(Optional)* API keys for **openFDA**, **SAM.gov**, and **USPTO** to raise rate limits and unlock direct access
- *(Optional, for deployment)* The [`gcloud` CLI](https://cloud.google.com/sdk/docs/install) authenticated against a Google Cloud project with **Cloud Run** and **Secret Manager** enabled

## Step 1: Clone the repository

```bash
git clone https://github.com/rtmdiyguy/predictive-business-opportunity-app.git
cd predictive-business-opportunity-app
```

## Step 2: Install dependencies

```bash
npm install
```

<Tip>
  You can substitute `bun install` if you prefer Bun. A `bun.lock` file is checked in alongside `package-lock.json`.
</Tip>

## Step 3: Configure environment variables

Copy the example file and fill in your keys:

```bash
cp .env.example .env
```

At a minimum, set `GEMINI_API_KEY`. `APP_URL` is auto-injected when running on Cloud Run, but you can set it manually for local testing.

```env .env
# Required — used by the server-side Gemini proxy
GEMINI_API_KEY="your-gemini-api-key"

# URL where this instance is reachable. Defaults to http://localhost:3000 locally.
APP_URL="http://localhost:3000"

# Optional — raises rate limits on the corresponding federal APIs
USPTO_API_KEY=
SAM_GOV_API_KEY=
OPENFDA_API_KEY=
SEC_EDGAR_USER_AGENT=
```

<Warning>
  All third-party credentials live **server-side only**. The browser never receives them directly — the client calls proxy endpoints like `/api/analyze`, `/api/scrape/url`, `/api/scrape/linkedin`, and `/api/ingest/live`, which in turn talk to Gemini and external data sources on the server. Never expose `GEMINI_API_KEY` to client code.
</Warning>

### Firebase configuration

Firestore is used to persist the canonical entity dictionary, the knowledge graph, and NER training data. Firebase settings are read from `firebase-applet-config.json` at the repo root by `src/lib/firebase.ts`. Populate this file with your own project values before running the app:

```json firebase-applet-config.json
{
  "projectId": "your-firebase-project-id",
  "appId": "your-web-app-id",
  "apiKey": "your-web-api-key",
  "authDomain": "your-project.firebaseapp.com",
  "firestoreDatabaseId": "(default)",
  "storageBucket": "your-project.firebasestorage.app",
  "messagingSenderId": "your-sender-id",
  "measurementId": "",
  "oAuthClientId": "",
  "recaptchaSiteKey": ""
}
```

<Note>
  These identifiers are public-facing Firebase Web SDK values, not secrets. Real secrets (Gemini, scraper tokens) still belong in `.env` locally or in Secret Manager in production. Publish read/write rules for your Firestore instance via `firestore.rules` before opening the app to real users.
</Note>

## Step 4: Start the development server

```bash
npm run dev
```

The script runs `tsx server.ts`, which starts the Express server with Vite middleware for hot-reloaded React. Open [http://localhost:3000](http://localhost:3000) to load the dashboard.

You should see:

- The **Signal Sandbox** populated with sample federal signals
- The **Entity Extraction Studio** and **API Developer Studio** panels
- Live scraper log output when you trigger a scrape from the UI

## Step 5: Build for production

```bash
npm run build
npm start
```

- `npm run build` runs `vite build` to bundle the React client and `esbuild` to compile the Express server to `dist/server.cjs`.
- `npm start` boots the compiled server (`node dist/server.cjs`). By default it also listens on port 3000.

Use `npm run lint` (`tsc --noEmit`) to type-check the codebase before shipping.

## Step 6: Deploy to Google Cloud Run

The app is designed to run on Cloud Run with all secrets sourced from **GCP Secret Manager** — no `.env` file ships with the container.

1. Store each secret in Secret Manager:

   ```bash
   echo -n "your-gemini-api-key" | gcloud secrets create gemini-api-key --data-file=-
   echo -n "your-scraper-token"  | gcloud secrets create scraper-token  --data-file=-
   ```

2. Build and push a container image (a `Dockerfile` is included at the repo root):

   ```bash
   gcloud builds submit --tag gcr.io/PROJECT_ID/market-marksman:latest
   ```

3. Deploy to Cloud Run and bind the secrets as environment variables:

   ```bash
   gcloud run deploy market-marksman-api \
     --image gcr.io/PROJECT_ID/market-marksman:latest \
     --set-secrets GEMINI_API_KEY=projects/PROJECT_ID/secrets/gemini-api-key:latest \
     --set-secrets SCRAPER_BEARER_TOKEN=projects/PROJECT_ID/secrets/scraper-token:latest \
     --region us-central1 \
     --allow-unauthenticated
   ```

Cloud Run injects `APP_URL` automatically and scales the service to zero when idle. The production security model — server-side key resolution, the `x-cloudscheduler-secret` header used by the `/api/cron/ingest` background sweep, and the canonical entity resolution pipeline — is documented alongside the app's Phase 1 architecture notes.
