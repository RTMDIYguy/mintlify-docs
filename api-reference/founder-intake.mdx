## Overview

The `founderIntake` tRPC router powers the Founder Intake Agent on the marketing site. The agent runs embedded on the `/start` front door and in the LiveChat widget. It qualifies founders through conversation, recommends an offer, and saves every visitor's conversation, even before the visitor shares a name or email.

The router exposes two public procedures:

- `founderIntake.respond` generates the next assistant reply in an intake conversation.
- `founderIntake.captureLead` records a qualified lead and sends intake notifications.

## founderIntake.respond

Takes the conversation so far plus any lead details already collected and returns the next assistant reply. When the LLM is unavailable, the router falls back to a rule-based response that still moves the conversation forward.

### Input

| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `messages` | array | Yes | 1 to 24 chat messages. Each message has `role` (`user` or `assistant`) and `content` (1 to 4000 characters). |
| `lead` | object | No | Lead context collected so far: `name`, `email`, `company`, `painPoint`, and `interest`, all optional strings. |
| `visitorKey` | string | No | Per-browser key generated on the client, up to 64 characters. Lets the router remember a visitor who has not shared an email yet. |

### Example request

```ts
const result = await trpc.founderIntake.respond.mutate({
  messages: [{ role: "user", content: "I want to systemize my business." }],
  lead: { interest: "Business Systems Diagnostic" },
  visitorKey: "v_3f1c2a9e-8b7d-4c1e-9a2f-5d6e7f8a9b0c",
});
```

### Output

| Field | Type | Description |
| :--- | :--- | :--- |
| `reply` | string | The next assistant message to display. |
| `stage` | string | Conversation stage: `qualify`, `capture`, or `recommend`. |
| `recommendedOffer` | string or null | Offer the agent recommends, if any. |
| `recommendedCta` | string or null | Call to action tied to the recommended offer. |
| `shouldCaptureLead` | boolean | Whether the client should show the lead capture form. |
| `collected` | object | Lead fields the agent extracted from the conversation. |

If the founder mentions a known offer (Founder Roundtable, Business Systems Diagnostic, or Ownable OS), the router records it as the lead's `interest`.

## founderIntake.captureLead

Records a qualified lead. Creates a contact submission, sends an intake notification email, and sends an auto-reply to the founder.

### Input

| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `name` | string | Yes | At least 2 characters. |
| `email` | string | Yes | Must be a valid email address. |
| `company` | string | No | Founder's company. |
| `painPoint` | string | No | The problem the founder described. |
| `interest` | string | No | Offer the founder is interested in. |

### Output

```json
{
  "success": true,
  "submissionId": "sub_1788486000000",
  "message": "Lead captured successfully."
}
```

## Anonymous visitor capture

Every `founderIntake.respond` turn saves the visitor's profile and transcript. The router upserts a visitor profile using the visitor's email when one is known, or the `visitorKey` otherwise. Email is optional on visitor profiles, so a visitor who never shares an email is still recorded.

When an anonymous visitor shares an email later in the conversation, the router stamps that email onto the existing anonymous profile instead of creating a new one.

### Generating a visitor key

The marketing site creates the key once per browser and stores it in `localStorage`, then sends it with every intake turn. Use the same pattern if you call the router from your own client:

```ts
export function getVisitorKey(): string {
  let key = localStorage.getItem("agentlab_visitor_key");
  if (!key) {
    key = `v_${crypto.randomUUID()}`;
    localStorage.setItem("agentlab_visitor_key", key);
  }
  return key;
}
```

### Claiming anonymous history at signup

The signup request sends the same browser's `visitorKey`. When the new account's email has no matching visitor profile, AgentLab attaches the anonymous profile for that browser key to the new workspace. The founder's pre-signup intake history follows them into their account.

### Privacy and limits

- The visitor key identifies a browser, not a person. Clearing browser storage or switching devices produces a new key.
- Each saved transcript keeps the latest 12 turns and at most 8KB of text.
- The `/start` page tells visitors what is stored and links to the privacy policy.

## The /start front door

`/start` is the public front door for the marketing site. The Home page's primary call to action links to it. The page includes:

- The Founder Intake Agent embedded as the main interactive element.
- A privacy note describing what the agent stores.
- A signup call to action.

## Auto lead capture in LiveChat

The floating LiveChat widget appears only on the public landing page and only for signed-out visitors. Authenticated users and inner OS pages never show it. It uses the same intake conversation as `/start`, including the visitor key.

The intake chat shows quick-select interest options (for example, offer names). Selecting an option sends the choice straight through `founderIntake.respond` as a user message instead of only pre-filling the input. The chat then:

- Records the selection as the lead's `interest` and, if none was set, its `painPoint`.
- Displays the agent's reply.
- Opens the lead capture form when the response sets `shouldCaptureLead` or the lead is still missing a name or email.

This means a founder who selects an interest option gets qualified and captured without typing a message.
